# Полная генеалогическая карта: готовность к публикации

Дата: 2026-09-05. Решение: **не выпускать полную базу в публичный production сейчас**. Техническая основа есть, но интеграция источника, границы публикации, индексируемые страницы и редакционная подготовка не завершены. Проверка read-only; приложение, БД и deployment не изменялись.

## Что подтверждено

- OBSERVED, production: `/ru/shezhire-tree` и `/kk/shezhire-tree` отвечают 200, title описывает 47 родов. Есть `index, follow`, canonical и взаимные hreflang RU/KK. Это публичная старая версия; в просмотренном HTML признаков полного источника нет.
- OBSERVED, production: поиск Адай `/api/genealogy/search?q=Адай&source=repo&locale=ru` и дети Наймана `/api/genealogy/children?node=tribe:naiman&source=repo&locale=ru` отвечают 404 **HTML**, не JSON-ошибкой неизвестного узла. Новый API дерева на этих публичных маршрутах не доступен.
- OBSERVED, production: sitemap содержит 173 URL, включая две страницы карты; не содержит страниц импортированных записей. `robots.txt` закрывает `/_next/` и `/api/`. Локальная SEO-правка уже убирает запрет `/_next/`, но на production она ещё не действует.
- OBSERVED, local report: снимок от 2026-08-20 содержит 794 594 записи, 27 768 с `locked`, глубина 31, один узел с отсутствующим именем. Это статистика сохранённого снимка, не свежий подсчёт в БД и не подтверждение исторической достоверности связей.
- OBSERVED, code: полный Neon-адаптер сохранён в исходном checkout `/Users/am/Documents/Projects/01 Active/skezire/src/lib/genealogy-data.ts`, но не включён в текущий worktree. В текущем `src/lib/genealogy-data.ts` есть Supabase/repository-реализация.

HTTP-снимок: [full-genealogy-live-2026-09-05.json](full-genealogy-live-2026-09-05.json). Проверки известных API выше выполнены дополнительно после снимка, чтобы отличить отсутствующий маршрут от ошибочного ID `root`.

## Техническая сторона

| Находка | Практическое значение | До публикации |
| --- | --- | --- |
| Источник Neon не интегрирован в worktree | Подключение прежней базы не входит в проверенную сборку | Перенести адаптер с явной конфигурацией; подтвердить фактический источник и объём |
| DB-ветка начальной загрузки возвращает корень и детей, не путь к `highlight` | Прямой переход к глубокой записи не раскрывает нужную цепочку | Загрузка и проверка пути по внешнему ID; регрессия на существующие ссылки 47 родов |
| При ошибке публичного источника возможен fallback к repository | HTTP 200 не доказывает, что работает большая карта | Различать отказ источника и намеренный выбор малого дерева; диагностика источника |
| В preview-адаптере `GENEALOGY_INCLUDE_PRIVATE=1` обходит `is_public`; API не требует входа | Перенос preview-конфигурации в публичный сайт может раскрыть закрытые записи | Публичный источник только из разрешённых записей; отдельная защита preview. Не переносить private-флаг |
| Дети выбираются без пагинации; глубина не измеряет ширину дерева | Очень широкая ветвь может дать большой ответ и перегрузить интерфейс | Измерить максимальную ширину, объём ответа и время поиска/раскрытия на полной базе; ограничивать выдачу по факту измерений |

Схема БД содержит полезные ограничения: private по умолчанию, запрет публикации locked-узлов, основание редакционной проверки и публичный путь родителей. Их наличие в файле миграции не подтверждает применение и состояние целевой БД. Нужны read-only сверка схемы, total/public/locked, корня и непрерывности разрешённых путей.

Предыдущие успешные build, восемь тестов и мобильные проверки относились к дереву 47 родов и общей навигации. Они не доказывают работоспособность полной базы. Нагрузочный тест, полная DB-проверка, свежие CWV и GSC rendering полной карты — UNAVAILABLE в этом аудите.

## SEO

1. **Большая интерактивная карта сама по себе не создаёт индексируемый каталог.** Потомки загружаются через fetch по кнопке; у импортированных узлов нет `href`. Google не нажимает кнопки для раскрытия контента. Для выбранных публичных ветвей нужны стабильные адреса с основным содержимым при открытии, обычные ссылки между страницами и включение в sitemap. [Google: lazy loading](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading), [crawlable links](https://developers.google.com/search/docs/crawling-indexing/links-crawlable).
2. **`?highlight=` сейчас — состояние инструмента.** Canonical всех вариантов ведёт на общую карту. Это разумно для одного инструмента, но не является архитектурой отдельных SEO-страниц ветвей. Для индексируемой страницы нужен собственный содержательный документ и согласованная каноникализация; не следует механически делать self-canonical каждому клику. [Google: canonicalization](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).
3. **Метаданные и структурированные данные не адаптированы к полному источнику.** В `src/app/[locale]/shezhire-tree/page.tsx` title, description, intro и CollectionPage/ItemList привязаны к 47 родам независимо от выбранной БД. Каталог 47 родов может оставаться отдельным разделом, но должен быть явно отделён от количества генеалогических записей.
4. **На live закрыты JS/CSS в `/_next/`.** Это препятствие для корректного рендеринга поисковиком. Удаление запрета уже подготовлено локально; после deployment нужно проверить действующий robots и отрисованный HTML в GSC. `/api/` не нужно открывать поисковикам ради индексации: основное содержимое индексируемой страницы должно быть доступно без действий пользователя.
5. **Не рекомендована массовая генерация 794 594 SEO-страниц.** Сначала отбор разрешённых полезных ветвей с ясным содержанием, затем проверка индексирования и поисковых запросов. Большой объём сам по себе не нарушение; риск возникает при массовом создании малоценных страниц ради поиска. Не дописывать вымышленные биографии ради объёма. [Google: spam policies](https://developers.google.com/search/docs/essentials/spam-policies).

## Тексты и достоверность

- Адаптер отдаёт имя, технический тип, ID и наличие детей; поиск также отдаёт цепочку. Он не передаёт в карточку источник конкретного утверждения, описание, степень проверки или ссылку на историю. В `InteractiveTree.tsx` описание и «Подробнее» появляются только при наличии `summary`/`href`, которых у импортированных узлов нет.
- Текущий вводный текст обещает переход к истории рода, но для большинства импортированных записей такого назначения не реализовано. Нужен текст, соответствующий фактическим возможностям полного источника, на RU/KK.
- `max_depth=31` — вычисленная глубина связей в снимке. Она не доказывает «31 документально подтверждённое поколение». Род, подрод, персона и технический узел нельзя автоматически считать одним видом сущности только по глубине.
- Для публикуемой ветви нужны различимый заголовок (одноимённые записи не должны сливаться), родительская цепочка, доступные потомки, атрибуция источника и дата снимка, статус проверки и понятный способ сообщить об ошибке. Дополнительный исторический текст нужен там, где для него есть источники; объём текста не назначается искусственно.
- Политика проекта требует проверки происхождения и персональных данных до публикации. `locked=false` само по себе не означает разрешение на публичный выпуск. Подтверждённых оснований публикации всей базы в просмотренных материалах нет.

## Рекомендуемый порядок

1. Проверить полную базу в защищённом preview: источник, корректность путей, поиск, широкие ветви, отсутствие утечки закрытых записей.
2. Подготовить публично разрешённую выборку и соответствующие тексты инструмента. Доступность посетителю и индексирование поисковиком решать отдельно; `noindex` не защищает персональные данные.
3. Добавить SEO-страницы только для выбранных содержательных ветвей, согласовать их с существующей энциклопедией без дублирования; RU/KK, canonical, ссылки, sitemap и атрибуция.
4. Выполнить preview-проверки, затем deployment с последующей проверкой robots/HTTP/GSC. Для общего релиза дополнительно остаются известные lint/CI и платёжный риск из [map-integration.md](../map-integration.md).

Это оценка готовности по публичным HTTP-ответам, локальному коду, сохранённому отчёту снимка и независимому read-only ревью. Фактический состав production-БД, работоспособность прежнего защищённого preview, индексирование конкретных записей, текущая скорость полной карты и поисковый спрос по её узлам не проверены. Предсказаний трафика нет.
