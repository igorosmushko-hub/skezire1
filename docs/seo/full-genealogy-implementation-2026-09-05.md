## Реализовано

- Полный источник использует Neon, требует `GENEALOGY_DATABASE_URL`, `GENEALOGY_SOURCE`, `GENEALOGY_ROOT_KEY`. Отсутствующая/сломанная конфигурация не подменяется 47 родами. Ненастроенный старый Supabase RPC не используется как альтернативный полный источник.
- `GENEALOGY_INCLUDE_PRIVATE=1` запрещён в этом публичном приложении. В этой первоначальной версии публичность требовала `is_public`, отсутствия `locked`, даты проверки и непустого основания. Требование отсутствия `locked` признано ошибочным и исправлено в продолжении: `genealogy-release-progress-2026-09-05.md`. В новой версии остаются `is_public`, дата проверки, непустое основание и полная цепочка предков. Проверяется вся цепочка до настроенного корня в том же SQL-запросе, который выдаёт детей. Отдельно требуется read-only DB credential; этот код не подтверждает права существующего deployment role.
- Прямые ссылки по canonical node key и однозначному числовому внешнему ID раскрывают цепочку предков. Циклы, неоднозначность, закрытый родитель и неизвестный узел отклоняются. Старые `highlight=naiman` явно открывают подписанное справочное дерево энциклопедии; это совместимость URL, а не fallback ошибки БД.
- Дети выдаются порциями по 100. Частичный путь не считается полным списком детей; последующие порции сохраняют выбранную ветвь. На телефоне при ошибке очередной порции список остаётся, доступна повторная загрузка.
- Обновлены RU/KK metadata, тексты, JSON-LD, sitemap и robots. Снимок Tumalas 20.08.2026, 794 594 записи и глубина 31 описаны как статистика снимка, не текущий публичный объём или доказанная история поколений.
- Для содержательных индексируемых страниц переиспользуется существующая энциклопедия: 47 родов и четыре раздела на двух языках. Новые страницы импортированных записей не созданы: нет подтверждённого редакционного отбора и оснований их публикации. Архитектура и границы — `genealogy-page-architecture.md`.

## Уточнение смысла locked после проверки первоисточника

Проверка публичного кода и API Tumalas показала: locked используется для ограничения редактирования; записи с locked=1 выдаются без авторизации. Поэтому прежнее обозначение всех 27 768 locked-записей как закрытых для просмотра некорректно. Текущий фильтр NOT locked в нашей реализации требует пересмотра отдельно от is_public и проверки оснований публикации. Подробные доказательства: `tumalas-locked-verification-2026-09-05.md`. В рамках проверки код, БД и deployment не изменялись.
