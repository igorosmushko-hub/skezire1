## Пробелы исходной модели

`genealogy_nodes` хранит только одно имя, одного родителя и импортные метаданные. Нет entity type, relationship type, дат/эпохи/смерти, биографии, contributor ID, цитат, библиографии, согласия, source license или reviewers identity. `reviewed_at + publication_basis` не заменяют provenance конкретных фактов. `taipa` не используется для семантики UI.

`source:id:parent` годится для адреса строки снимка, но меняется при смене parent и не должен быть каноническим ID человека/рода. Импортёр фактически требует однозначного дерева; альтернативные источники, несколько родителей и конфликтующие утверждения нужно представлять отдельно.

У исходного importer snapshot time может быть mtime файла; фиксировать как claimed/derived time, пока нет журнала загрузки. `begin_genealogy_import` старой схемы снимает текущую публичность до batch-загрузки; в рамках исследования его вызывать нельзя. Release-миграция усиливает ограничения reimport; staged/versioned ingestion проектировать отдельно, не запускать старый importer для обновления проверенных узлов.

Репозиторный каталог не равен онтологии. Например, Жаныс имеет отдельную статью среди материалов Старшего жуза и одновременно является ветвью Дулат. Редакционная задача уже исправляет объяснение этого различия; нельзя трактовать каталог статей как список sibling-сущностей одного ранга. Neoн корень — `Қазақ`, а его дети — 12 групп, не три жуза; копирование глубин в этнографические типы неверно.
