# Tumalas → Skezire: read-only исследование базы и решение следующего этапа

**Срез Neon: 2026-09-05 18:39:35 UTC. Результат: 18 родовых сущностей — конкретный стартовый набор для редакционного/правового review карты; вместе с уже существующим корневым контейнером это 19 узлов с полным кандидатным путём. Это не разрешение публикации.** Вне этого набора остаются **794575** записей, которые нужно держать закрытыми и классифицировать дальше. В Neon по-прежнему **3 публичных и 794591 private** записей; новых публикаций — **0**.

Не следует читать «18» как общее количество родов/ветвей во всём снимке: это ограниченный, воспроизводимый и подкреплённый источниками seed-набор. Нынешних полей недостаточно, чтобы достоверно разделить остальные записи на исторических и живых людей. Исследование даёт реальные очереди проверки и показывает, какие дополнительные доказательства нужны.

```sh

  docs/research/2026-09-05-tumalas/queries.json \
  /private/tmp/skezire-new-profile.json \
```

Файл env содержит `GENEALOGY_DATABASE_URL` и `GENEALOGY_SOURCE`; его не отправлять в чат/Git. Для этой сессии использован уже существовавший reader из `/private/tmp/skezire-neon-reader.env`; файл может не сохраниться до следующего сеанса. Runner выполняет одну `REPEATABLE READ, READ ONLY` транзакцию и сохраняет hash manifest. Роль `skezire_preview_reader`: SELECT разрешён, INSERT/UPDATE/DELETE запрещены. Из базы сохранены агрегаты и ограниченные родовые кандидаты; личные имена длинного хвоста, полный снимок и credentials в документацию не выгружены.

## Классы A/B/C/D: результат правила v1

E — отдельная характеристика доказательства и в сумму классов не входит. В таблице B и C означают **кандидатные очереди**, а не установленную историчность или факт жизни.

| Класс | Реальное число | Основание правила | Confidence и действие |
|---|---:|---|---|
| A: подтверждённый родовой смысл в seed-наборе | **18** | Exact ID + name + expected parent + taipa, сверка контекста с указанным внешним источником | Высокий качественный confidence **типа группы**. Кандидаты review карты, публикация ещё не одобрена |
| B-review: возможные исторические персоны | **446** | Имя содержит пробел и отдельный титул: батыр/хан/би/сұлтан/султан/ақын/акын/жырау; не A/C | Низкий для историчности, статус жизни неизвестен. Проверять личность/эпоху/источник |
| C-signal: приоритет privacy-review | **294** | Имя содержит конечный патронимический маркер ұлы/улы/қызы/кызы/ович/евич/овна/евна; не A | Признак формы имени, **не доказательство живого человека**. Оставить private |
| D: неопределённые | **793836** | Остальные, включая корневой контейнер | Низкий/неизвестный. Private по умолчанию; root отдельно как навигационный container |
| **Всего A+B+C+D** | **794594** | Приоритет `A → C → B → D` | Записи не считаются дважды |

Пересечение B/C-сигналов на текущем срезе — **0**. Приоритет всё равно зафиксирован для будущих снимков. В D находятся **793835** записей за вычетом известного корня. Поэтому объём вне кандидатного набора: `446 + 294 + 793835 = 794575`.

**Число доказанно живых и число доказанно исторических людей во всём снимке: UNAVAILABLE.** В этом проходе ни одной персональной identity/death-проверки не выполнено; это не утверждение, что в данных нет исторических или живых людей. Для всех записей вне A и отдельно распознанного container риск живого человека остаётся неизвестным/возможным. C не является верхней границей privacy-риска.

`B` нельзя расширять простым поиском титула: широкая regex даёт **3683** совпадения, а **3097** имён — отдельные слова вроде «Батыр»/«Хан». Поэтому рабочее правило требует составного имени; даже оставшиеся 446 могут содержать современное имя или ошибку. Пробел сам по себе тоже не доказывает ФИО.

## Практический отбор A и E

Сопоставлены два внешних библиографических основания:

- Учебник «Қазақстан тарихы», Ә. Төлеубаев и др., Алматы: Мектеп, 2010, 2-е издание, ISBN 978-601-293-191-4. Печатная **с. 81**, PDF page index 80: список 11 племён Старшего жуза. [PDF на e-history.kz](https://e-history.kz/storage/upload/library_kk_files/iblock/f23/f2310f0d5a63c06ed525ec0c86812669.pdf#page=81). Проверены текст и страница; перечисление подтверждает тип/традиционный состав, не биологическую генеалогию всех потомков и не лицензию на книгу.
- Институт литературы и искусства имени М. О. Ауэзова, «Қосымшалар», раздел «Ру атаулары», словарные статьи Дулат, Жалайыр, Суан. [Первоисточник издателя](https://auezovinstitute.kz/?page_id=9125). Для matching взяты только прямо указанные названия ветвей, совпадающие с непосредственным родителем в Neon. Ссылка на этот источник найдена в предыдущем редакционном фактчеке; относящиеся к matching фрагменты перечитаны в этом этапе.

Внешне подтверждены **18 утверждений о родовом типе** и **7 связей традиционного деления** — E-overlay данного исследования. Это подмножество A; не дополнительные 18 строк. Для root→11 родов совпадение source parent не выдаётся за независимо подтверждённое отцовство. Книга отдельно позволяет предложить 11 `member_of(Ұлы жүз)` в новом knowledge layer; таких рёбер в source tree сейчас нет.

Область E ограничена: это сверка с внешним изданием, независимым от нашего текста. Не установлено, пользовался ли Tumalas той же книгой; считать Tumalas + книгу двумя статистически независимыми свидетельствами нельзя. Верифицированные биологические родительские связи — **0 в этом исследовании**. В самой Neon отдельного статуса E/evidence layer пока нет; новые факты и ссылки сохранены в документации, не в БД.

Другие написания/непрямые пути не включались автоматически: например, `Байтүгел` в источнике против `Байтүгей` в Neon требуют ручного identity resolution. `Шақшам` требует отдельного источника. Подрод и эпонимическая персона могут иметь одно имя: в новом графе это разные сущности/утверждения. Seed-группу нельзя разворачивать автоматически на всех потомков.

**Путь карты проверен SQL:** все 18 кандидатов связаны до container ID 1 внутри набора; всего **19** узлов. Из них **3 уже имеют is_public**, **16 пока private**. Это условная достижимость после одобрения всего набора и его рёбер, а не 19 уже публичных узлов. Только 11 A-узлов сейчас имеют непосредственно публичного родителя; глубже нужны отдельные решения для пути. Root можно использовать как навигационный контейнер без заявления, что он человек/доказанный предок.

Для автоматического triage пригодны:

1. Сверка с управляемым evidence-справочником по имени **и контексту** с exact ID/parent/taipa на конкретном снимке. Изменение поля снимает match; ID сам по себе не вечное доказательство.
2. Наблюдаемые лексические маркеры — только для очереди разметки B/C/D.
3. Структурные проверки parent/depth/taipa — для целостности и отбора небольшого review-пакета, не для возраста или достоверности родства.

Не пригодны как разрешающие признаки: locked, глубина/число поколений, лист/не-лист, ширина ветви, «древнее» имя, популярность имени, большой/малый ID, даты импорта, один taipa, отсутствие жалоб. Словарь репозитория даёт **4157** совпадений строк, из них **4142** ниже уровня 2: это сильная демонстрация риска одноимённости. Нельзя открывать все совпадения. Для числовых 90%/95% confidence нет gold-разметки и измеренной ошибки; проценты не назначались.

## Решение и следующий шаг

**Можно сейчас:** закрытый provenance pilot для 18 сущностей, разметка источников/типов связей, независимая проверка спорных matching, подготовка dev-проекции и privacy-тестов. Продолжать исследование B/C/D независимо от юридической неопределённости. Существующий curated SEO-слой улучшать на проверенных источниках; новые Tumalas node pages не генерировать.

**Не выпускать до решения:** расширение публичной выдачи даже на 16 seed-private записей, любые B/C/D, открытый full-tree preview, полный export/API, массовые SEO-страницы. Не применять source-lock или новую provenance migration в production без отдельного решения.

**Блокеры:** правовая квалификация reuse исходной базы и обработки идентифицируемых людей; подтверждение фактического региона/потоков Neon и требований РК; редакционное одобрение конкретных фактов/рёбер; отсутствие достоверных признаков жив/умер; не внедрённый provenance/decision layer. Три существующих public-флага не закрывают эти вопросы: их basis относится к protected preview.

Следующий технический этап — описанный в [architecture-and-policy.md](architecture-and-policy.md) **непубличный pilot knowledge layer на 18 группах + root**, с сохранением источника каждого факта и отдельной выдачей разрешённых рёбер. Юристу передать [конкретную повестку и требуемые решения](legal.md), без credentials и полного снимка. После этого подготовить точный dry-run manifest публикации; решение о применении остаётся отдельным.

## Проверки и ограничения завершённого этапа

Выполнены живые read-only SQL-запросы; проверены read-only/reader privileges, арифметика всех классов/глубин/степеней, source matching, candidate path и согласованность manifest hashes. Просмотрены текущий checkout, release-worktree и релевантные предыдущие отчёты. Проведено независимое ревью исследовательского пакета. Фактические результаты runnable-проверки сохранены в `validation.txt`.

Runtime-код, production schema, роли, `is_public`, данные Neon и настройки deployments не изменялись. Полная база повторно не скачивалась, владельцам Tumalas запросы не отправлялись. Сборка/линт приложения и browser QA в этом этапе **не запускались**: изменения ограничены документацией и локальным инструментом read-only исследования; не заявляем готовность production или безопасность нового runtime на основании этого отчёта.
